Supabase: база вместо таблицы

Чем база данных отличается от таблицы в файле, какой путь проходит запрос со страницы до базы и почему каждый видит только то, что ему разрешено.

Когда таблица перестаёт справляться

Сейчас ваши данные — таблицы CSV в папке data/: пилотные строки (урок 14) и черновик сборщика с вердиктами критика (уроки 19–20). На сотнях строк начинаются знакомые беды. «LCC-ICCG» в одной строке и «LCC ICCG» в другой — для таблицы это два разных фермента. В числовой столбец попало «65 F». Двое правят файл одновременно, и чьи-то правки пропадают.

База данных хранит те же строки, но вместе с правилами, которые она сама и соблюдает1. Температура — только число. Единица — обязательна. Измерение нельзя записать за несуществующий фермент. Таблица такие ошибки принимает молча, база отказывается. И правки двоих не теряются: если двое правят одну строку, вторая правка ждёт, пока закончится первая, и видит уже её результат2.

Supabase — облачный сервис, внутри которого работает база PostgreSQL3. Вокруг неё Supabase добавляет вход для пользователей и готовое API (урок 7) — окошко, через которое к базе обращается страница сайта.

Две оговорки

Бесплатный проект засыпает, если неделю к нему не обращались: данные целы, страница перестаёт получать ответы. Будят его кнопкой Resume project в панели — в течение года после засыпания. Вернулись к курсу через месяц — сначала разбудите проект. И автоматических резервных копий на бесплатном тарифе нет — о копиях урок 25.

Таблицы, связи и одно слово

Образ

Библиотечный каталог. В карточке книги не переписывают биографию автора — там стоит номер его карточки. Исправили год рождения автора в одном месте — исправилось для всех его книг.

Так устроены ваши три таблицы из урока 16. У каждого фермента есть номер строки (E1, E2…). Строка измерения хранит не название, а этот номер — это связь. Переименовали фермент один раз — все его измерения «переехали» вместе с ним. Записать измерение за номер, которого нет, база не даст.

Слово «ключ»

В учебниках номер строки называют «первичным ключом». В нашем курсе «ключ» значит только ключ доступа — пароль для программ (урок 7). Номер строки так и зовём: номер строки.

Запрос: вопрос на языке базы

К базе обращаются запросом на языке SQL. Он читается почти как английская фраза: «выбери номер фермента, значение и источник из измерений, где параметр — оптимум температуры и значение не меньше 60»:

select enzyme_id, value, source_id from measurements where parameter = 't_opt' and value >= 60;

В ответе — номера ферментов, а не названия: названия лежат в соседней таблице. Как соединить их одним запросом, разберём в уроке 27. Писать запросы самим не нужно: запрос пишет агент, а вы проверяете ответ на контрольных вопросах (урок 17)5. Уметь стоит одно — прочитать в общих чертах: из какой таблицы, с каким условием.

Попробуйте сами

Таблица измерений учебной мини-базы: 12 строк. Двигайте порог — меняется условие в запросе, и база отбирает строки.

Номера ферментов: E1 IsPETase, E2 FAST-PETase, E3 HotPETase, E4 LCC-ICCG, E5 PHL7, E6 TfCut2, E7 ThermoPETase. Данные условные: названия настоящие, значения близки к опубликованным по порядку величин.

Вход и путь запроса

Чтобы база знала, кто пришёл, нужен вход. В этом курсе он через Google: вы нажимаете «Войти», Google подтверждает почту, и Supabase выдаёт странице пропуск — подписанную запись «это такой-то». Дальше каждый запрос идёт с этим пропуском. Вот что происходит, когда вы отмечаете урок пройденным:

Правила доступа по строкам

Главное отличие от таблицы — шаг 5. Правило доступа по строкам (Row Level Security, RLS) — условие, которое база проверяет на каждой строке при каждом запросе. Строки, не прошедшие условие, для запроса просто не существуют.

Живой пример — этот курс. В таблице ai_progress (пройден ли урок) записать строку можно только свою, а читать — всем учащимся из списка курса: для общей страницы прогресса. В ai_notes (ваши записи к заданиям) читать может только автор.

Защищает не страница, а правило в базе.

Страница обращается к базе с публичным ключом. Это пропуск для страницы: он открыт всем и сам по себе ничего не разрешает — разрешают правила RLS. Кто-то напишет свою страницу с этим ключом — база всё равно не отдаст ему чужие записи. Есть и секретный ключ, который правила обходит, — о нём урок 25.

Частая ошибка — и почему она частая

В PostgreSQL таблица без RLS отдаёт все строки тому, кому открыта. Supabase годами открывал новые таблицы странице автоматически — удобно, но опасно6. С 2026 года в новых проектах таблица закрыта для страницы, пока доступ не выдали явно. RLS при создании таблицы в панели включается сам, а при создании командой SQL — нет: в файле схемы его включают отдельной строкой.

Как проверить правила без кода: откройте страницу в режиме инкогнито, без входа, — видно только задуманное? Войдите другим аккаунтом — чужих записей нет? Попросите агента сделать запрос с одним публичным ключом, без пропуска: закрытые таблицы должны вернуть пусто или отказ.

Биотехнология

Правило «температура от −20 до 150, единица обязательна» ловит строку «65 F» или «338» без единицы в момент записи, а не через месяц на графике. Правило «статус „подтверждено критиком“ ставит только критик» отделяет непроверенное от проверенного прямо в базе.

Свои проекты

Расследование о фундациях: таблицы «фундации», «люди», «участие в советах». Вопрос «кто сидит в советах двух фундаций сразу» — один запрос, а в таблице — ручная сверка сотен строк. Черновые заметки журналиста видит только он сам.

Сноски
  1. Как эти правила устроены и как их записывают — в бесплатной книге Е. Моргунова: от создания таблиц и связей до запросов, с упражнениями на учебной базе авиаперевозок. Читать выборочно: главы про типы данных и ограничения — как раз о «правилах, которые база соблюдает». Postgres Professional: «PostgreSQL. Основы языка SQL» (книга, рус., по главе за вечер).
  2. Связанные изменения база тоже проводит целиком или никак: либо записаны и фермент, и все его измерения, либо ничего. Это свойство называется транзакцией. Короткий пример с банковским переводом в учебнике PostgreSQL на русском объясняет, зачем это нужно и что видят другие, пока транзакция не закончена. Документация PostgreSQL: «Транзакции» (учебник, рус., 10 мин).
  3. PostgreSQL — база данных с открытым кодом; её ядро развивается почти 40 лет, начиная с проекта Калифорнийского университета в Беркли. Работает и в банках, и на домашних серверах.
  4. По страницам supabase.com/pricing и «Project Pausing» на 10.11.2026; там же 1 ГБ для файлов. Платный тариф Pro — от 25 $ в месяц, его проекты не засыпают. У Сергея для одного из домашних проектов стоит маленький таймер, который раз в несколько дней обращается к базе, чтобы она не уснула.
  5. Насколько хорошо модели пишут SQL, меряют на наборах вопросов с известными ответами. На наборе BIRD лучшие системы на осень 2026 дают верный ответ примерно в 83 % вопросов, люди-специалисты — в 93 %. Вывод: проверка контрольными вопросами — не перестраховка. BIRD: таблица результатов (сайт, англ., 5 мин).
  6. Ошибка не учебная. В марте 2025 года исследователь Мэтт Палмер проверил 1645 сайтов, собранных конструктором Lovable поверх Supabase, и у 170 из них (около 10 %) нашёл таблицы, которые публичным ключом читались, а иногда и правились без всякого входа. Урок: проверять не «есть ли правило», а «верно ли оно». Matt Palmer: Statement on CVE-2025-48757 (заметка, англ., 10 мин). Смена умолчаний с 30 мая 2026 года для новых проектов и с 30 октября — для всех: Supabase Changelog (англ., 5 мин).

Главное
  • База хранит данные вместе с правилами: типы, обязательные поля, связи между таблицами.
  • Запрос на SQL пишет агент; вы читаете его в общих чертах и проверяете ответ контрольными вопросами. Одна строка ответа — одно измерение, не один фермент.
  • Вход даёт странице пропуск, и база знает, кто спрашивает.
  • Доступ защищают правила RLS внутри базы, а не страница и не скрытность публичного ключа. Проверяйте их входом без пропуска.
Задание на 10 минут

Зарегистрируйтесь на supabase.com (можно через GitHub из урока 23 или Google) и создайте бесплатный учебный проект — в уроке 25 он станет вашей тестовой базой. В разделе Table Editor создайте таблицу enzymes с полями «название» (текст) и «температурный оптимум» (число) и внесите три строки.

Затем впишите в числовое поле слово «горячо» и сохраните. Запишите, что произошло, и найдите в панели, включено ли для таблицы RLS.

Сквозной проект · шаг 24

Перенесите данные в Supabase в безопасном порядке. Сначала попросите агента разложить принятые строки (после критика и вашей выборки, урок 20) по трём файлам из TZ.md: data/enzymes.csv, sources.csv, measurements.csv. Создайте второй, рабочий проект. Поручите агенту написать по TZ.md файл схемы sql/schema.sql — три таблицы, связи, правила значений и включение RLS на каждой — и закоммитить его (урок 23). Вы открываете SQL Editor в панели, вставляете файл и запускаете. Затем загружаете три CSV из data/: Table Editor → Insert → Import data from CSV. Секретный ключ агенту не нужен, доступ для страницы пока не давайте — он понадобится в уроке 26.

Сверка: число строк до и после, три случайные строки по исходнику, пять контрольных вопросов — запросы пишет агент, запускаете вы в SQL Editor. Запишите в журнал запись «проверка» с расхождениями.
