GitHub: история и откат

Как история версий позволяет смело менять проект: снимки с подписью, черновики-ветки и возврат к любой точке — и чего в этой истории быть не должно.

Зачем история

Агент переписал раздел урока, и тест перестал работать. Вопрос «как было вчера?» без истории версий означает поиск по старым копиям в почте. С историей это одна команда.

Git1 — программа, которая хранит историю папки проекта: каждое сохранённое состояние, кто и зачем его сделал. GitHub — сайт, где эта история лежит копией в облаке, где её видят другие и откуда сайт можно опубликовать.

Не путать

Git работает и без интернета, прямо в папке на вашем компьютере. GitHub — один из сайтов, где хранят копию истории. История — главное, сайт — удобство.

Коммит — снимок с подписью

Коммит — снимок всех файлов проекта в один момент, плюс подпись: кто, когда и зачем. Каждый коммит знает предыдущий, поэтому из них складывается цепочка — линия времени проекта. Неизменённые файлы Git не копирует заново, так что тысяча снимков почти не занимает места.

Живой пример — этот курс. В ТЗ записано правило: осмысленный коммит после каждой сессии. Вот часть настоящей истории за 10 ноября 2026, от старых к новым:

  • 7256213 Сессия 1: каркас курса, уроки 1–4 из прототипа, вход Google…
  • 3b22cc5 Урок 1 переписан по замечаниям Сержа; планшет заменён полосой прогресса
  • 9fe5f0c Урок 1 разделён на два: «Токены и предсказание» и новый «Что происходит внутри»

Семь знаков слева — короткое имя коммита2. По нему к снимку можно вернуться в любой момент. Если Сергей решит, что урок 1 был лучше одним, разделение отменяется ссылкой на 9fe5f0c.

Хорошая подпись

Отвечает на вопрос «что изменилось и зачем», а не «что я делал». «Единицы приведены к °C, чтобы сравнивать оптимумы» — хорошо. «Правки» или «fix» — через месяц ничего не скажут.

Ветка — черновик

Ветка — отдельная линия снимков, отходящая от основной. Основную обычно зовут main — это чистовик. Рискованное изменение делают в ветке. Получилось — ветку сливают с основной, и её коммиты входят в чистовик. Не получилось — ветку бросают, а чистовик не тронут.

Агенту удобно поручать работу в ветке: «сделай в отдельной ветке, покажи, что изменилось, сливать буду я». Тогда решение о чистовике остаётся за человеком.

Откат

Вернуть прошлое можно двумя способами, и разница важна.

Отмена новым коммитом

Git создаёт ещё один снимок, в котором неудачное изменение убрано, а всё остальное, сделанное позже, на месте. История честная: видно и ошибку, и её отмену. Это безопасный путь (команда revert).

Перемотка назад

Проект возвращают к старому снимку целиком, всё после него выбрасывается — и хорошее тоже. В общей истории, которую уже видели другие, так делать опасно (команда reset).

Попробуйте сами

История учебной таблицы ферментов из четырёх коммитов. В коммите 3 агент «привёл единицы»: пересчитал температуры в кельвины, а подпись столбца оставил «°C». Потом в коммите 4 добавил новый фермент. Нажимайте на коммиты, чтобы увидеть снимок, затем исправьте ошибку одним из двух способов.

Данные условные. Проверка — как в уроке 14: значения в разумных пределах и контрольный вопрос «сколько ферментов с оптимумом не ниже 60 °C» (по источникам — 3).

Граница отката

Git возвращает файлы: тексты, код, описания таблиц. Строки, которые агент уже испортил в живой базе Supabase, откат файлов не вернёт. Для данных нужны резервные копии — урок 22.

Что хранят в репозитории, а что нет

Репозиторий — папка проекта вместе со всей её историей. Хранят в нём то, что вы пишете и меняете: тексты, код, ТЗ, описание таблиц (SQL-файлы), журнал, файл правил проекта.

Не хранят: ключи и пароли, большие выгрузки данных, личные данные людей, временные файлы. Для этого есть файл-список исключений .gitignore: перечисленное в нём Git не замечает. В проекте этого курса там стоят, например, файлы .env — так принято называть файл с ключами.

Если ключ всё-таки попал в коммит

Удалить файл следующим коммитом мало: ключ остался в истории, и любой, у кого есть копия, его найдёт. Ключ надо сменить в сервисе, старый — отозвать. GitHub по умолчанию не даёт отправить в открытый репозиторий ключи известных ему форматов3, но это страховка, а не правило.

Открытый репозиторий этого курса содержит только папку сайта4. В нём есть публичный ключ Supabase — это не ошибка, почему — в уроке 22.

Биотехнология

Инструкция для агента-сборщика лежит в репозитории. После правки «бери и стабильность тоже» доля ошибок у критика выросла с 4 до 11 %. История показывает, какие именно строки инструкции изменились, и правку можно отменить одним коммитом, сохранив всё остальное.

Свои проекты

Сайт фундации на GitHub Pages: агент обновил польскую версию и задел русскую. Откат одного коммита — и через минуту сайт снова прежний. Ветка «новый-дизайн» живёт неделями, не трогая работающий сайт.

Сноски
  1. Git написал Линус Торвальдс в 2005 году для разработки ядра Linux. Сейчас это основной инструмент истории версий в мире программ.
  2. Полное имя — 40 знаков, вычисленных из содержимого снимка: изменится хоть одна буква — изменится имя. Поэтому подменить прошлое незаметно нельзя.
  3. Защита от отправки секретов для пользователей GitHub включена по умолчанию и действует для открытых репозиториев (документация GitHub, актуально на ноябрь 2026). Ключ необычного формата она может не узнать.
  4. Основная история курса — в папке на сервере Сержа. Для публикации из неё отдельной веткой выделяется история одной папки site/ и отправляется на GitHub, откуда GitHub Pages показывает сайт.

Главное
  • Коммит — снимок проекта с подписью «что и зачем»; к любому снимку можно вернуться.
  • Рискованное делают в ветке; в чистовик сливает человек.
  • Безопасный откат — новый коммит, отменяющий одно изменение; перемотка выбрасывает и хорошее.
  • Ключи, личные данные и большие выгрузки в репозиторий не кладут; утёкший ключ меняют.
