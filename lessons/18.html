Анатомия агента

Любого агента можно описать четырьмя полями: роль, инструменты, память, права. Заполнив их, вы заранее знаете, что агент сделает, чего не сможет и где может навредить.

Рабочая среда модуля

С этого модуля работаем в Claude Code в папке проекта (урок 13). Запасной путь — приложение Claude с доступом к папке: в нём получатся задания на 10 минут и ручная часть шагов (карточки, выборка, расчёт). Субагенты, правила прав и параллельный сбор там не получатся.

Одна модель — разные агенты

В этом модуле у вас появятся сборщик, который вытаскивает цифры из статей, и критик, который их проверяет. Модель внутри у них одна. Чем же они отличаются?

Сначала два слова. Тот сеанс Claude Code, с которым вы разговариваете, — главный агент. Часть работы он может поручить субагенту — помощнику со своей инструкцией и своим окном (подробно — урок 21).

Сборщик и критик — одна и та же модель в разных «должностях» (агент как модель с инструментами — урок 11). Различает их не ум, а описание1. Субагенту можно дать и модель подешевле (урок 21).

Образ

Новый лаборант. Ему дают должностную инструкцию, допуск к определённым приборам, лабораторный журнал и правило: что можно делать самому, а что — только с разрешения заведующего. Без этих четырёх вещей даже хороший специалист в чужой лаборатории бесполезен или опасен.

У агента ровно те же четыре поля. Их удобно держать в виде карточки.

Роль и инструменты

Роль задаётся инструкцией — текстом, который ложится в окно агента первым (урок 5). Хорошая инструкция короткая и проверяемая: одна задача, точный вид результата, признак готовности и что делать при сомнении. «Помоги с ферментами» — не роль. «Из каждой статьи извлеки оптимум температуры и pH; к каждой цифре приложи дословную цитату; если цифры нет — напиши „нет данных“» — роль2.

Инструменты — список действий агента: прочитать файл, найти фразу, записать строку, запустить команду в терминале (урок 13). Чего нет в списке, того агент сделать не может. Это и ограничение, и защита: агент без инструмента «отправить письмо» никому ничего не отправит.

Как это выглядит в Claude Code

Попросите: «Создай субагента collector в папке .claude/agents/ по этой карточке» — и вставьте карточку. Агент запишет обычный текстовый файл в формате Markdown (урок 13). Точка в начале имени папки значит «служебная»: в окне папок такие по умолчанию скрыты3.

---
name: collector
description: извлекает оптимумы T и pH из статей
tools: Read, Grep, Edit
model: sonnet
---
v1. Из статьи извлеки оптимум T и pH. К каждой цифре —
дословная цитата и место. Нет цифры — «нет данных».
Строки дописывай в data/draft_measurements.csv.

Между чёрточками — шапка: имя, когда звать, инструменты, модель. Ниже — роль. Позвать: «Используй субагента collector для статьи…». Актуально на ноябрь 2026.

Осторожно

Без инструмента, чтобы открыть источник, агент обычно не говорит «не могу», а отвечает по памяти модели — с ошибками из урока 6. Поэтому статьи кладут в папку articles/.

Память — это файлы

Веса модели заморожены (урок 3), а окно живёт один сеанс (урок 5). Всё, что должно пережить сеанс, записывается в файлы. В начале работы агент читает их — и «вспоминает». Поэтому память — это просто то, что агент знает в начале, и всё это попадает в окно.

У Claude Code два таких механизма4. Файл правил CLAUDE.md пишете вы. Автоматические заметки агент ведёт сам — в служебной папке Claude Code. Открыть их можно командой /memory. Это обычный текст: неверную заметку правят или удаляют. Субагент заметок главного не получает и начинает с чистого окна — это пригодится критику (урок 20).

Не записали решение — следующий запуск о нём не узнает. Журнал journal.md — не бюрократия, а память команды агентов.

Права: что можно без спроса

Права отвечают на вопрос «что агент делает сам, что — после вашего „да“, а что запрещено совсем». Режим из урока 13 задаёт общую строгость. Точнее работают правила тремя списками: запретить, спросить, разрешить. Их видно и правят командой /permissions, а хранятся они в файле .claude/settings.json проекта:

"deny": ["Read(./.env)"],
"ask":  ["Edit(./data/measurements.csv)", "Bash(rm *)"]

Первая строка запрещает читать файл с секретами. Вторая требует вашего «да» на любую правку принятой таблицы и на удаление файлов. Запрет проверяется первым, правило «спросить» срабатывает в любом режиме, даже в Auto5. Правила по путям действуют на весь проект. Поэтому каждому агенту дают свой файл для записи и узкий список инструментов в карточке.

Правило «только Manual» из урока 13 здесь заканчивается: когда эти правила записаны, можно перейти в Accept edits. Режим Auto — после урока 22.

Читать файлы своей папки агент может без спроса. Чтение ничего не меняет, но всё прочитанное уходит в окно и к провайдеру. Поэтому секреты держат вне досягаемости (урок 25).

Права выдают под задачу, а не из доверия.

Критику не нужно право исправлять таблицу: его дело — вердикт. Сборщику не нужно право удалять. Чем уже права, тем меньше вреда от любой ошибки — своей или навязанной чужим текстом, который агент прочитал (урок 22).

Инструкция — не замок

Фраза «никогда не удаляй файлы» в инструкции — просьба. Модель почти всегда её выполнит, но гарантии нет: документация Claude Code прямо говорит, что правила из файлов — это контекст, а не принудительная настройка. Гарантию дают правила прав6.

Биотехнология

Сборщик читает папку с PDF и дописывает строки в черновик. Удалить строку или поменять принятую таблицу он не может — таких прав нет. Даже если он перепутает статьи, основная таблица цела, а ошибка видна в черновике.

Свои проекты

В файле правил этого курса записано: «ничего не удалять без подтверждения», «публиковать только с согласия Сергея». Это память — и просьба. Чтобы публикация физически не прошла без «да», команду отправки на сайт ставят в список «спросить».

Сноски
  1. Та же мысль в привычной для статей схеме «агент = модель + планирование + память + инструменты», с разбором видов памяти: Selectel: «Как устроены LLM-агенты: архитектура, планирование и инструменты» (статья, рус., 2025, 14 мин). Код в середине можно пропустить.
  2. Как писать инструкции «на правильной высоте» — не жёсткий список «если — то» и не расплывчатое «помоги» — и почему начинать стоит с короткой, дописывая её по замеченным ошибкам: Anthropic: Effective context engineering for AI agents (статья, англ., сентябрь 2025, 25 мин). Там же — инструменты, заметки и субагенты: по сути, все четыре поля карточки.
  3. Файл можно положить и в ~/.claude/agents/ — тогда помощник доступен во всех проектах. Кроме полей из примера, в шапке бывают запрещённые инструменты и своя память субагента. Команда /agents в свежих версиях только напоминает, где лежат файлы. Документация: Create custom subagents (англ., 20 мин), проверено 10.11.2026.
  4. В начале сеанса из автоматических заметок загружаются первые 200 строк (до 25 КБ), остальное агент дочитывает по необходимости. Как посмотреть и поправить, что агент записал о проекте: How Claude remembers your project (документация, англ., 15 мин). Полезно открыть рядом со своей папкой.
  5. Порядок проверки — запретить, спросить, разрешить; первое совпадение решает. Правила по путям ловят встроенные инструменты чтения и правки и распознанные команды терминала, но не любую программу, которую агент запустит сам. Документация Claude Code: Configure permissions и Choose a permission mode, ноябрь 2026.
  6. Ещё на шаг надёжнее — ограничение на уровне операционной системы: агент физически видит только свою папку и ходит только на разрешённые адреса. Как это сделано в Claude Code и почему вопросов стало на 84 % меньше: Anthropic: Making Claude Code safer with sandboxing (статья, англ., октябрь 2025, 10 мин).

Задание на 10 минут

Откройте Claude Code в папке проекта (или запасной путь). Заполните для него карточку из четырёх полей. Спросите агента: «Какие у тебя сейчас инструменты? Что ты можешь сделать без моего подтверждения? Какие файлы ты читаешь в начале работы?» Ответ сверьте с экранами /permissions, /mcp и /memory: о себе модель тоже может ошибиться (урок 6).

Запишите карточку, одно расхождение между ответом агента и экраном и одно право, которое для вашей задачи лишнее.

Сквозной проект · шаг 18

Карточки четырёх агентов проекта, по 2–3 предложения роли, список инструментов, файлы памяти и права в три строки: «сам», «со спросом», «запрещено».

  • Сборщик — извлекает цифры из статей в черновик data/draft_measurements.csv (урок 19).
  • Чистильщик — до проверки приводит единицы к одной (°C) и помечает дубли в черновике. Ничего не удаляет.
  • Критик — сверяет каждую строку с источником; записи у него нет, вердикты он возвращает главному (урок 20).
  • Аналитик — отвечает на вопросы к принятой базе (урок 27); только чтение.

Попросите Claude Code записать каждую карточку в .claude/agents/, а в /permissions — правила из примера урока. В journal.md — запись «решение»: какие агенты и почему.
