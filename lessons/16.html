Анатомия агента

Любого агента можно описать четырьмя полями: роль, инструменты, память, права. Заполнив их, вы заранее знаете, что агент сделает, чего не сможет и где может навредить.

Одна модель — разные агенты

В уроке 9 агент был моделью, которой дали инструменты и разрешили работать по кругу: подумал, сделал, посмотрел результат. В модуле 5 агентов будет несколько, и все они — одна и та же модель в разных «должностях». Различает их не ум, а описание.

Образ

Новый лаборант. Ему дают должностную инструкцию, допуск к определённым приборам, лабораторный журнал и правило: что можно делать самому, а что — только с разрешения заведующего. Без этих четырёх вещей даже хороший специалист в чужой лаборатории бесполезен или опасен.

У агента ровно те же четыре поля. Их удобно держать в виде карточки.

Роль и инструменты

Роль задаётся инструкцией — текстом, который ложится в окно агента первым (урок 4). Хорошая инструкция короткая и проверяемая: одна задача, точный вид результата, признак готовности и что делать при сомнении. «Помоги с ферментами» — не роль. «Из каждой статьи списка извлеки оптимум температуры и pH; к каждой цифре приложи дословную цитату; если цифры нет — напиши „нет данных“» — роль.

В Claude Code такую роль можно оформить как субагента — отдельного помощника, описанного одним файлом: имя, когда его звать, какие инструменты, какая модель, а ниже текст инструкции1.

Инструменты — список действий, доступных агенту: прочитать файл, открыть страницу, сделать запрос к базе, записать строку. Чего нет в списке, того агент сделать не может, как бы ни старался. Это не только ограничение, но и защита: агент без инструмента «отправить письмо» никому ничего не отправит.

Осторожно

Если у агента нет инструмента, чтобы открыть источник, он не скажет «не могу». Скорее, он ответит по памяти модели — со всеми ошибками из урока 5. Сборщику обязательно нужен доступ к самим статьям.

Память — это файлы

Веса модели заморожены (урок 3), а окно живёт один сеанс (урок 4). Поэтому у агента нет памяти в человеческом смысле. Всё, что должно пережить сеанс, записывается в файлы: правила проекта, список статей, журнал «что уже обработано», сама таблица. В начале работы агент читает их — и «вспоминает».

Как это устроено у Claude Code

Каждый сеанс начинается с чистого окна. Знания переносят два механизма: файл CLAUDE.md с правилами, который пишете вы, и автоматические заметки, которые агент ведёт сам. Оба загружаются в начале каждого сеанса2. Актуально на ноябрь 2026.

Следствие простое: если решение не записано, следующий запуск о нём не узнает. Журнал проекта — не бюрократия, а память команды агентов.

Права: что можно без спроса

Права отвечают на вопрос «что агент делает сам, что — после вашего „да“, а что запрещено совсем». В Claude Code по умолчанию чтение файлов в папке проекта идёт без вопросов, а правка файлов, команды и обращения в интернет — с вопросом. Правила задаются тремя списками: запретить, спросить, разрешить; запрет проверяется первым и перевешивает разрешение3.

Права выдают под задачу, а не из доверия.

Критику не нужно право исправлять таблицу: его дело — поставить отметку. Сборщику не нужно право удалять. Чем уже права, тем меньше вреда от любой ошибки — своей или подсунутой извне (подробно в уроке 24).

Инструкция — не замок

Фраза «никогда не удаляй файлы» в инструкции — просьба. Модель почти всегда её выполнит, но гарантии нет: документация Claude Code прямо говорит, что правила из файлов — это контекст, а не принудительная настройка. Гарантию даёт только запрет в правах.

Биотехнология

Сборщик читает папку с PDF и дописывает строки в файл-черновик. Удалить строку или поменять уже проверенную он не может — таких прав нет. Даже если он перепутает статьи, основная таблица цела, а ошибка видна в черновике.

Свои проекты

На сервере ftm у Claude Code есть общий файл правил: ничего не удалять без подтверждения, системные пакеты ставить только с согласия Сергея, после новой службы обновлять реестр сервера. Это память и права в одном файле. А за последнее слово отвечает настройка прав.

Сноски
  1. Файл в формате Markdown лежит в папке проекта .claude/agents/ (или в ~/.claude/agents/ — тогда помощник доступен во всех проектах). В шапке файла — имя, описание «когда звать», список инструментов, модель и режим прав. Каждый такой помощник работает в своём окне контекста. Актуально на ноябрь 2026.
  2. Из автоматических заметок в начале сеанса загружаются первые 200 строк (до 25 КБ); остальное агент дочитывает по необходимости. Документация Claude Code, раздел «How Claude remembers your project», ноябрь 2026.
  3. В английской документации: deny, ask, allow. Есть и режимы для всего сеанса: обычный (спрашивать при первом использовании инструмента), «принимать правки», «только план», автоматический с проверкой каждого действия отдельной моделью и режим без вопросов. Последний разумен только в изолированной среде. Актуально на ноябрь 2026.

Задание на 10 минут

Возьмите любого помощника, которым вы уже пользуетесь: Claude Code в своей папке, проект в Claude с инструкциями, бота. Заполните для него карточку из четырёх полей. Где поле не можете заполнить — спросите самого агента: «Какие у тебя сейчас инструменты? Что ты можешь сделать без моего подтверждения? Какие файлы ты читаешь в начале работы?»

Запишите карточку и одно право, которое у агента есть, но для вашей задачи лишнее.

Сквозной проект · шаг 16

Составьте карточки четырёх агентов проекта: сборщик, критик, чистильщик (единицы и дубликаты), аналитик (запросы и графики). Для каждого — роль в 2–3 предложениях, список инструментов, файлы памяти и права в три строки: «сам», «со спросом», «запрещено». Сохраните карточки в журнал проекта: в уроках 17–19 вы будете их уточнять.
