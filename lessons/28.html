Публикация: страница базы в интернете

Как поручить агенту страницу поиска по вашей базе, проверить, что гость видит только проверенное, и выложить её в интернет.

Страница поиска — тоже ТЗ

Письмо из соседней лаборатории

«Говорят, у вас есть сводка по ферментам для ПЭТ. Какие работают при 65 °C?» Послать три файла CSV? Дать доступ к панели Supabase, где можно случайно удалить таблицу? Лучший ответ — ссылка: коллега открывает страницу, вводит 65 и видит только проверенные строки с источниками.

Пока в базу (урок 26) можно заглянуть только из панели. Нужна страница поиска: открыл адрес — нашёл фермент. Это отдельная задача агенту, и ставится она как задача на базу (урок 18): коротким ТЗ с приёмкой.

ТЗ: страница поиска
1. Поле поиска по названию фермента.
2. Фильтр «оптимум не ниже, °C».
3. Таблица: фермент, значение,
   условия, источник (DOI-ссылка),
   статус.
4. Данные — из Supabase
   с публичным ключом.
   Секретного ключа в папке нет.
5. Гость видит только
   подтверждённые строки. Фермент
   без таких строк не показывается.
6. Под таблицей — что значат
   статусы; пустое значение
   пишется «нет данных».
Приёмка: ответы на контрольные
вопросы совпадают с запросом
в SQL Editor по подтверждённым
строкам.

Подтверждённые — «подтверждено критиком» или «подтверждено человеком» (урок 22).

Где живёт страница

В отдельной папке pet-enzymes-site/ — рядом с pet-enzymes/, не внутри. У неё свой открытый репозиторий и свой TZ.md. Агента открывают в этой папке. Адрес базы и публичный ключ можно дать ему прямо в чате: публичный ключ — не секрет (урок 27).

Что увидит гость: два слоя и приёмка

Пункт 5 страница сама не обеспечит: защищает база (урок 26). Поэтому первая часть работы — ещё в папке проекта. Агент пишет файл sql/access.sql, рядом со схемой, с обоими слоями:

  • доступ к таблицам — гостю только на чтение, ко всем трём;
  • правило по строкам на измерениях — только подтверждённые.

Запись гостю закрыта дважды: доступ выдан лишь на чтение, правил на запись нет. Дальше — путь из урока 27: агент проверяет файл на тестовой базе, в SQL Editor рабочей его запускаете вы.

Главная проверка · числа примера180 → 140

В панели 180 измерений, на странице — 140, и среди них ни одной строки «не проверено». Поэтому ответы страницы сверяют с запросом по подтверждённым строкам, а не по всем.

Проверить оба слоя можно без кода. Попросите агента сделать два запроса с одним публичным ключом: чтение измерений должно вернуть 140 строк, попытка записи — отказ. А готовую страницу откройте с телефона через мобильную сеть: она работает не только у вас дома.

Адрес: от имени к компьютеру

Каждый компьютер в интернете находится по числовому IP-адресу, например 185.199.108.153 — один из адресов GitHub Pages. Номера никто не помнит, поэтому есть домен — имя вроде belhome.cc. Домен покупают у компании-регистратора на год, порядка 10–15 $.

Имена в адреса переводит DNS — справочная служба интернета, как телефонная книга. Записи в ней двух главных видов: A — «имя → числовой адрес» и CNAME — «имя → другое имя», переадресация «спросите у такого-то»1. У этого курса одна строка в DNS: agent → sergpanfilov.github.io. Имя слева от домена — поддомен.

Свой домен не обязателен. GitHub Pages — бесплатная публикация страниц прямо из репозитория — даёт адрес по имени репозитория: имя.github.io/pet-enzymes-site. Одно условие: на бесплатном GitHub публикуют только из открытого репозитория2. Вот зачем странице отдельная папка: история проекта остаётся закрытой.

Кому видна страница

У страницы на GitHub Pages варианта два: открыта всем или не опубликована. Входа нет: гость — это каждый, включая вас. Для нашей базы «открыта всем» годится: данные из опубликованных статей, непроверенное база не отдаёт. Решение запишите в журнал.

Коллега откроет ссылку через две недели

Бесплатная база за это время уснёт (урок 26). Страница откроется — её отдаёт GitHub, — но без данных. Посылаете ссылку — загляните в панель и разбудите проект. Надолго — поручите агенту автоматический запрос к базе раз в день-два.

Если у вас есть свой сервер, как у Сергея

Тогда уровней доступа три: открыто всем, за входом, только своя частная сеть. Вход перед сайтом ставит Cloudflare — компания-посредник: её серверы стоят между гостем и сайтом, выдают сайт по защищённому адресу и могут спросить вход. Её служба Access пропускает только адреса почты из списка3.

Домашний компьютер стоит за роутером, и тот правильно не пускает входящие соединения — когда снаружи стучатся к вам. Стучатся в порт — номер «двери» для определённой программы. Открыть порт — открыть дверь всем подряд. Туннель Cloudflare устроен иначе: маленькая программа на сервере сама звонит в Cloudflare и не кладёт трубку, как жилец, который позвонил консьержу. Гости приходят к Cloudflare, а он передаёт их просьбы по этой линии4.

Два разных замка

Access решает, пустить ли к сайту вообще. Вход Google на этом курсе — другое: он говорит базе, кто вы внутри сайта, а RLS решает, какие строки вам отдать (урок 26). Оба через Google, но это разные входы.

Попробуйте сами

Соберите маршрут запроса. Выберите адрес, затем нажимайте блоки по порядку — от браузера до того, кто отдаёт данные. Лишние блоки в маршрут не входят.

Маршруты упрощены, но устройство настоящее: так работают страницы на GitHub Pages и адреса Сергея (актуально на ноябрь 2026). Адрес страницы ферментов — условный.

Биотехнология

Страница поиска ферментов открыта на GitHub Pages: гость видит 140 подтверждённых измерений, строки «не проверено» база ему не отдаёт. В журнале запись «решение»: «открыто всем — данные из опубликованных статей; черновые строки закрыты правилом».

Свои проекты

belhome.cc: главная и курсы открыты, семейное дерево — за входом Access, служебный пульт — только из своей сети. Каждый новый адрес — одна строка в DNS и одна запись «решение» в журнале: что открыли и почему.

Сноски
  1. Лучший способ понять DNS — завести свои записи и посмотреть, кто к ним обращается. В песочнице Mess with DNS (проект Джулии Эванс) вы получаете собственный поддомен, добавляете записи, в том числе CNAME, и видите живой журнал запросов. Ничего не сломать. Mess with DNS (интерактив, англ., 20–40 мин).
  2. На тарифах GitHub Pro и выше можно публиковать и из закрытого репозитория, но сама страница всё равно видна всем. Пошаговая инструкция на русском — от выбора папки до проверки адреса; её удобно дать агенту вместе с ТЗ. Документация GitHub: «Создание сайта GitHub Pages» (инструкция, рус., 10 мин), проверено 10.11.2026.
  3. Access входит в Cloudflare Zero Trust; бесплатный тариф — до 50 пользователей (актуально на ноябрь 2026). Работает только для адресов, которые ведут через Cloudflare, то есть нужен свой домен; страницу на github.io им не закрыть. Частная сеть у Сергея — Tailscale: попасть в неё может только устройство, которое он сам добавил.
  4. В настройках Cloudflare записано, какое имя в какой туннель вести; программа запускается сама при включении компьютера и перезванивает после сбоя. Она называется cloudflared; по документации Cloudflare она устанавливает только исходящие соединения, серверу не нужен публичный адрес. Туннели есть на всех тарифах, включая бесплатный. В документации есть схема: Cloudflare Docs: Cloudflare Tunnel (документация, англ., 15 мин).
Частые вопросы
Как показать страницу только двум коллегам?Проще всего — открытая страница с подтверждёнными данными из открытых статей. Если данные закрытые, нужен вход по списку адресов почты: вход Supabase плюс правило по строкам «только вошедшим». Это отдельная задача агенту, на вечер.
Исправил строку в базе. Страницу публиковать заново?Нет. Страница каждый раз берёт строки из базы — новое значение видно сразу.
Отправлять теперь надо дважды?Да, это два репозитория: правки базы и журнала — из pet-enzymes/, правки страницы — из pet-enzymes-site/. Каждая сессия отправляет своё.
Гость видит публичный ключ. Может он исчерпать мой бесплатный тариф запросами?Теоретически да: в тариф входит 5 ГБ исходящего трафика в месяц (актуально на ноябрь 2026). Для учебной страницы риск мал; расход виден в панели, раздел Usage.
Ферменты и источники гость видит целиком?Да: названия и номера DOI — не черновые данные. Непроверенными бывают числа, а они в измерениях — под правилом по строкам.

Задание на 10 минут

Откройте Google Public DNS: запрос agent.belhome.cc. Это ответ справочной в машинном виде. Найдите в части "Answer" строку с "type": 5 — это CNAME; после "data" стоит имя, куда переадресует курс. Затем замените в адресной строке agent.belhome.cc на sergpanfilov.github.io, а CNAME — на A (запись «имя → числовой адрес»): увидите числовые адреса GitHub Pages.

Запишите оба ответа и одной фразой — путь от имени курса до адреса компьютера.

Сквозной проект · шаг 28

Время: вечер; можно в два приёма. Числа — из примера; у вас свои.

Сегодня — доступ и страница у себя.

  • В папке проекта pet-enzymes/, где у агента есть ключ тестовой базы. Поручите файл sql/access.sql с двумя слоями: доступ к трём таблицам только на чтение; правило по строкам «только подтверждённые» на измерениях. Агент запускает его на тестовой базе и проверяет её публичным ключом: чтение — 140 строк, запись — отказ. Затем файл запускаете вы в SQL Editor рабочей базы (урок 27). Коммит.
  • Создайте рядом с проектом папку pet-enzymes-site/ и положите в неё TZ.md с ТЗ страницы (6–8 строк, как в уроке).
  • Откройте агента в этой папке — новой сессией. Дайте ему адрес рабочей базы и её публичный ключ (панель → Project Settings → API Keys) и поручите страницу по ТЗ. Попросите ещё: если база не отвечает, страница пишет об этом словами, а не показывает пустую таблицу.
  • Приёмка. В панели 180 измерений, на странице 140, строк «не проверено» нет. Контрольные вопросы: ответы страницы совпадают с запросом по подтверждённым строкам.

Можно в другой день — публикация.

  • Поручите агенту открытый репозиторий pet-enzymes-site на GitHub и публикацию через GitHub Pages.
  • Откройте адрес с телефона через мобильную сеть.
  • Запись в журнал проекта, тип «решение»: адрес страницы, кому она видна и почему.
