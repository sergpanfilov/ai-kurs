Cloudflare и Obsidian: публикация и журнал

Как адрес в браузере находит нужный сервер, как одно открыть всем, а другое — только своим, и почему журнал решений нужен вам через полгода больше, чем сегодня.

Домен и адреса

Каждый компьютер в интернете находится по числовому адресу — как телефон по номеру. Номера никто не помнит, поэтому есть домен — имя вроде belhome.cc, как запись в телефонной книге. Домен покупают на год и продлевают.

Книгу ведёт DNS — справочная служба интернета. Браузер спрашивает её: «где agent.belhome.cc?» — и получает ответ. Ответ бывает двух видов: сам номер или переадресация: «спросите у такого-то». Вторая называется записью CNAME.

Живой пример — этот курс. В DNS у Сержа (их ведёт Cloudflare) стоит одна строка: agent → sergpanfilov.github.io1. Браузер идёт к GitHub, а GitHub Pages отдаёт файлы сайта из открытого репозитория (урок 21). Так же устроены klava.belhome.cc и dzik.belhome.cc. Каждый поддомен — имя слева от belhome.cc — это одна строка в DNS.

Туннель к домашнему серверу

С GitHub всё просто: его серверы открыты для всех. Домашний сервер — другое дело. Он стоит за роутером, а роутер правильно делает, что не пускает входящие соединения снаружи. Можно «пробросить порт» — открыть в роутере дверь. Но в открытую дверь стучат все подряд.

Cloudflare Tunnel2 решает это иначе. Маленькая программа на самом сервере сама звонит в Cloudflare и держит линию открытой. Запрос к drevo.belhome.cc (семейное дерево Сержа) приходит в Cloudflare и спускается по этой линии. Дверь в роутере закрыта, сервер разговаривает только с Cloudflare.

Образ

Не открывать подъезд каждому, а самому позвонить консьержу и не класть трубку. Гости приходят к консьержу, он передаёт их просьбы по телефону, а ваша дверь заперта.

Открытое и закрытое

У Сержа адреса делятся на три вида:

  • Открыто всем: главная belhome.cc, этот курс. Читать может любой.
  • Закрыто входом: семейное дерево и семейная стена. Перед ними стоит Cloudflare Access — шаг 3 на схеме. Он просит войти через Google и пропускает только адреса почты из списка семьи3. До сервера чужой запрос даже не доходит.
  • Только своя сеть: пульт управления сервером виден лишь с устройств Сержа через частную сеть. В интернете его нет вовсе.
Два разных замка

Курс открыт для чтения, но ваши записи к заданиям всё равно видите только вы. Это другой замок — правило доступа в базе (урок 20). Access решает, кто дойдёт до сайта; RLS — какие строки базы кому отдать.

Попробуйте сами

Соберите маршрут запроса. Выберите адрес, затем нажимайте блоки по порядку — от браузера до того, кто отдаёт страницу. Лишние блоки в маршрут не входят.

Маршрут упрощён, но устройство настоящее: так работают адреса Сержа (актуально на ноябрь 2026).

Журнал решений

Через полгода вы не вспомните, почему выбрали именно эту структуру таблиц или исключили статью S7. Журнал решений отвечает на вопрос «почему так», а не «что сделано». Одна запись — дата, решение, причина, что отвергли:

10.11.2026 · адрес курса agent.belhome.cc · ai.belhome.cc уже занят другим сайтом · отвергли: переносить тот сайт

Это настоящая запись из паспорта этого курса. Вести журнал удобно в Obsidian — программе для заметок. Заметки в нём — обычные текстовые файлы в папке на вашем компьютере (такая папка зовётся хранилищем)4. Их читают любой редактор и любой агент, они не пропадут вместе с сервисом. У Сержа так устроено хранилище «Жемчужин» — заметки синхронизируются с телефоном.

Файл правил — память агента

Агент не помнит прошлых сессий: каждая начинается с пустого окна (урок 4). Память ему дают файлы. Claude Code в начале каждой сессии сам читает файл правил CLAUDE.md5 — вы писали такой в уроке 12.

Правила говорят агенту, как работать. Журнал — что уже решено и почему.

На сервере Сержа в файле правил записано, например: «ничего не удалять без подтверждения», «новые проекты — только в папке Projects», «после новой службы сразу обновить реестр сервера». У каждого проекта есть паспорт README.md и журнал изменений CHANGELOG.md. Новая сессия читает их — и продолжает с того места, где остановилась прошлая.

Биотехнология

Страница поиска по базе ферментов публикуется на поддомене и закрывается Access: научный руководитель входит своим адресом Google, остальным она не видна. В журнале решений: «исключили измерения при pH ниже 6 — условия не промышленные; 14 строк».

Свои проекты

belhome.cc: главная и курсы открыты, семейные страницы — за входом Google, служебный пульт — только из своей сети. Каждый новый адрес — одна строка в DNS и одна запись в журнале инфраструктуры: что открыли и почему.

Сноски
  1. Так и рекомендует документация GitHub Pages для поддомена: запись CNAME на <пользователь>.github.io. Проверить запись может любой — например, в Google Public DNS (задание ниже).
  2. По документации Cloudflare: программа cloudflared устанавливает только исходящие соединения, серверу не нужен публичный адрес. Туннели доступны на всех тарифах Cloudflare, включая бесплатный (актуально на ноябрь 2026).
  3. Access входит в Cloudflare Zero Trust; бесплатный тариф — до 50 пользователей (актуально на ноябрь 2026).
  4. Формат Markdown: текст с простой разметкой вроде # заголовок. Obsidian бесплатен без ограничений; платные только синхронизация (Sync, 4–5 $ в месяц) и публикация (Publish, 8–10 $ в месяц) — актуально на ноябрь 2026. Синхронизировать можно и своими средствами.
  5. Документация Claude Code «How Claude remembers your project»: файлы CLAUDE.md загружаются в начале сессии — общий для всех проектов и свой в папке проекта.

Главное
  • DNS переводит имя в адрес или переадресует: поддомен — одна строка.
  • Туннель открывает домашний сервер наружу без открытых дверей в роутере.
  • Доступ решается на нескольких уровнях: открыто всем, за входом (Access), только своя сеть; данные внутри защищают правила базы.
  • Файл правил говорит агенту, как работать; журнал решений — что решено и почему.

Задание на 10 минут

Откройте Google Public DNS: запрос agent.belhome.cc и найдите в ответе, куда переадресует имя курса. Подставьте в адрес belhome.cc или любой знакомый сайт и сравните ответы.

Затем установите Obsidian (или откройте любой редактор заметок), заведите заметку «Журнал решений» и запишите три решения, принятые вами в этом курсе: дата, решение, причина, что отвергли.
