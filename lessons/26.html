Публикация: страница базы в интернете

Как поручить агенту страницу поиска по вашей базе, выложить её в интернет и решить, кому она видна.

Страница поиска — тоже ТЗ

Письмо из соседней лаборатории

«Говорят, у вас есть сводка по ферментам для ПЭТ. Какие работают при 65 °C?» Послать три файла CSV? Дать доступ к панели Supabase, где можно случайно удалить таблицу? Лучший ответ — ссылка: коллега открывает страницу, вводит 65 и видит только проверенные строки с источниками.

База в Supabase есть (урок 24), но заглянуть в неё пока можно только из панели. Нужна страница поиска: открыл адрес — нашёл фермент. Это отдельная задача агенту, и ставится она так же, как задача на базу (урок 16): коротким ТЗ с приёмкой.

ТЗ: страница поиска, папка site/
1. Поле поиска по названию фермента.
2. Фильтр «оптимум не ниже, °C».
3. Таблица: фермент, значение, условия,
   источник (ссылка на DOI), статус.
4. Данные — из Supabase с публичным ключом.
   Секретного ключа в site/ нет.
5. Гость видит только подтверждённые строки.
Приёмка: контрольные вопросы 1–5 дают
те же ответы, что запрос в SQL Editor.

Подтверждённые — со статусом «подтверждено критиком» или «подтверждено человеком» (урок 20). Пункт 5 — правило RLS (урок 24): агент пишет его в файл SQL, вы запускаете. Принимаете страницу как любую работу агента — контрольными вопросами (урок 17). А перед публикацией — проверка в режиме инкогнито, без входа: видно ровно то, что задумано, и ни строки «не проверено».

Адрес: от имени к компьютеру

Каждый компьютер в интернете находится по числовому IP-адресу, например 185.199.108.153 — один из адресов GitHub Pages. Номера никто не помнит, поэтому есть домен — имя вроде belhome.cc. Домен покупают на год и продлевают.

Имена в адреса переводит DNS — справочная служба интернета, как телефонная книга. Браузер спрашивает: «где agent.belhome.cc?» Ответ бывает двух видов: сам номер или переадресация «спросите у такого-то» — запись CNAME1. У этого курса одна строка в DNS: agent → sergpanfilov.github.io. Имя слева от домена — поддомен.

Свой домен не обязателен. GitHub Pages — бесплатная публикация страниц прямо из репозитория — даёт адрес вида имя.github.io/pet-enzymes. Одно условие: на бесплатном GitHub публикуют только из открытого репозитория2. Поэтому историю проекта держат закрытой, а для страницы заводят отдельный открытый репозиторий с одной папкой site/. Так устроен и этот курс. Публичный ключ в открытой папке — не утечка (урок 25).

Открыто, за входом, только своим

Решите, кому видна страница, и запишите решение в журнал. У Сергея адреса делятся на три вида:

  • Открыто всем: главная belhome.cc и этот курс.
  • За входом: семейное дерево. Перед ним стоит Cloudflare Access — проверка входа через Google перед сайтом: пропускает только адреса почты из списка3. Чужой запрос до сайта не доходит.
  • Только своим: пульт сервера виден лишь через частную сеть — сеть только своих устройств поверх интернета (у Сергея это Tailscale). Попасть может только устройство, которое вы добавили.
Два разных замка

Access решает, пустить ли к сайту вообще. Вход Google на этом курсе — другое: он говорит базе, кто вы внутри сайта, а RLS решает, какие строки вам отдать (урок 24). Оба через Google, но это разные входы.

Если у вас есть свой сервер, как у Сергея

Домашний компьютер стоит за роутером, и роутер правильно не пускает входящие соединения — когда кто-то снаружи сам стучится к вам. Стучатся в порт — номер «двери» компьютера для определённой программы. Открыть порт в роутере — значит открыть дверь всем подряд. Туннель Cloudflare устроен иначе: маленькая программа на сервере сама звонит в Cloudflare и не кладёт трубку, как жилец, который позвонил консьержу. Гости приходят к Cloudflare, а он передаёт их просьбы по этой линии. В его настройках записано, какое имя в какой туннель вести. Программа запускается сама при включении компьютера и перезванивает после сбоя4.

Попробуйте сами

Соберите маршрут запроса. Выберите адрес, затем нажимайте блоки по порядку — от браузера до того, кто отдаёт данные. Лишние блоки в маршрут не входят.

Маршруты упрощены, но устройство настоящее: так работают страницы на GitHub Pages и адреса Сергея (актуально на ноябрь 2026). Адрес страницы ферментов — условный.

Биотехнология

Страница поиска ферментов открыта на GitHub Pages: гость видит 140 подтверждённых измерений, строки «не проверено» база ему не отдаёт. В журнале запись «решение»: «открыто всем — данные из опубликованных статей; черновые строки закрыты правилом».

Свои проекты

belhome.cc: главная и курсы открыты, семейные страницы — за входом Google, служебный пульт — только из своей сети. Каждый новый адрес — одна строка в DNS и одна запись «решение» в журнале: что открыли и почему.

Сноски
  1. Лучший способ понять DNS — завести свои записи и посмотреть, кто к ним обращается. В песочнице Mess with DNS (проект Джулии Эванс) вы получаете собственный поддомен, добавляете записи, в том числе CNAME, и видите живой журнал запросов. Ничего не сломать. Mess with DNS (интерактив, англ., 20–40 мин).
  2. На тарифах GitHub Pro и выше можно публиковать и из закрытого репозитория, но сама страница всё равно видна всем. Пошаговая инструкция на русском — от выбора папки до проверки адреса; её удобно дать агенту вместе с ТЗ. Документация GitHub: «Создание сайта GitHub Pages» (инструкция, рус., 10 мин), проверено 10.11.2026.
  3. Access входит в Cloudflare Zero Trust; бесплатный тариф — до 50 пользователей (актуально на ноябрь 2026).
  4. Программа называется cloudflared; по документации Cloudflare она устанавливает только исходящие соединения, серверу не нужен публичный адрес. Туннели есть на всех тарифах, включая бесплатный. В документации есть схема: Cloudflare Docs: Cloudflare Tunnel (документация, англ., 15 мин).

Главное
  • Страница поиска — отдельная задача агенту: короткое ТЗ, приёмка контрольными вопросами.
  • Основной путь: страница на GitHub Pages из открытого репозитория, данные — из Supabase с публичным ключом.
  • Что видит гость, решает правило RLS в базе; перед публикацией его проверяют в режиме инкогнито.
  • Доступ бывает трёх уровней: открыто всем, за входом (Access), только своя сеть; решение пишут в журнал.
Задание на 10 минут

Откройте Google Public DNS: запрос agent.belhome.cc. Это ответ справочной в машинном виде. Найдите в части "Answer" строку с "type": 5 — это CNAME; после "data" стоит имя, куда переадресует курс. Затем замените в адресной строке agent.belhome.cc на sergpanfilov.github.io, а CNAME — на A: увидите числовые адреса GitHub Pages.

Запишите оба ответа и одной фразой — путь от имени курса до адреса компьютера.

Сквозной проект · шаг 26

Опубликуйте страницу поиска по своей базе. 1) Положите ТЗ страницы (5–7 строк, как в уроке) в TZ.md. 2) Поручите агенту сделать страницу в site/ и файл SQL, который открывает странице таблицы только на чтение (в шаге 24 доступа не было) и задаёт правило «гость видит только подтверждённые строки»; файл запускаете вы. 3) Примите страницу контрольными вопросами. 4) Проверьте в режиме инкогнито без входа: строк «не проверено» не видно. 5) Поручите агенту публикацию на GitHub Pages из отдельного открытого репозитория. 6) Откройте страницу с телефона. 7) Запишите в журнал запись «решение»: кому видна страница и почему.
