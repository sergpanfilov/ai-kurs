GitHub: история и откат

Как история версий позволяет смело менять проект: снимки с подписью, черновики-ветки и возврат к любой точке — и чего в этой истории быть не должно.

Зачем история

Вчера контрольный вопрос давал три фермента, сегодня — пять. Между «вчера» и «сегодня» агент поправил измерения. Что именно он изменил и как вернуть вчерашнее? В папке проекта pet-enzymes/ (урок 13) уже целое хозяйство: правила, журнал, ТЗ, принятые таблицы в data/. С историей «как было вчера» — одна просьба агенту.

Модуль 6

Обвязка (урок 11) — программа вокруг модели. Этот модуль — про хозяйство вокруг вашего проекта: история файлов, база, ключи и публикация. Всем этим управляет агент, решения — за вами.

Git1 — программа, которая хранит историю папки: каждое сохранённое состояние, кто и зачем его сделал. Папку вместе с её историей называют репозиторием. GitHub — сайт, где лежит копия репозитория: там её видят другие и оттуда можно опубликовать сайт.

Не путать

История живёт в папке на вашем компьютере, Git работает и без интернета. Копия на GitHub обновляется, только когда её отправляют (по-английски push) — сама она не обновится. Для этого компьютер один раз связывают с GitHub2. Открытый репозиторий видят все, закрытый — только те, кого вы пригласили.

Коммит — снимок с подписью

Коммит — снимок всех файлов проекта в один момент плюс подпись: кто, когда и зачем. Каждый коммит знает предыдущий, и из них складывается цепочка — линия времени проекта. Неизменённые файлы Git не копирует заново: тысяча снимков почти не занимает места.

Живой пример — этот курс. В его ТЗ записано: осмысленный коммит после каждой сессии. Вот три коммита за 10 ноября 2026 года, от старых к новым, — так они выглядят на GitHub:

  • 5e42b4b Сессия 1: каркас курса, уроки 1–4 из прототипа, вход Google…
  • c12be47 Урок 1 разделён на два: «Токены и предсказание» и новый «Что происходит внутри»
  • 5021713 Тесты убраны (кнопка «Отметить пройденным»)…

Семь знаков слева — короткое имя коммита. Оно вычислено из содержимого снимка и из имени предыдущего коммита. Измените старый снимок — сменится его имя, а за ним имена всех следующих, и это сразу видно. Поэтому подменить прошлое незаметно нельзя. По имени к снимку можно вернуться. Если Сергей решит вернуть тесты, он пишет агенту: «отмени коммит 5021713 новым коммитом».

Отсюда просьба в конце каждой сессии: «закоммить и отправь» — сделай снимок и обнови копию на GitHub.

Хорошая подпись

Отвечает на вопрос «что изменилось и зачем», а не «что я делал». «Единицы приведены к °C, чтобы сравнивать оптимумы» — хорошо. «Правки» или «fix» — через месяц ничего не скажут3.

Ветка — черновик

Ветка — отдельная линия снимков, отходящая от основной. Основную обычно зовут main — это чистовик. Рискованное изменение делают в ветке. Получилось — ветку сливают с основной, и её коммиты входят в чистовик. Не получилось — ветку бросают, чистовик не тронут.

Если в ветке и в чистовике изменили одну и ту же строку, Git не угадывает: он останавливается и показывает обе версии. Это называется конфликтом. Выбираете вы — или агент по вашему решению.

Агенту удобно поручать работу в ветке: «сделай в отдельной ветке, покажи, что изменилось, сливать буду я». Решение о чистовике остаётся за человеком4.

Откат

Вернуть прошлое можно двумя способами, и разница важна.

Отмена новым коммитом

Git создаёт ещё один снимок, в котором неудачное изменение убрано, а всё сделанное позже — на месте. История честная: видно и ошибку, и её отмену. Это безопасный путь (команда revert).

Перемотка назад

Проект возвращают к старому снимку целиком, всё после него выбрасывается — и хорошее тоже. Если историю уже отправили и её взял кто-то ещё, у него останется старая цепочка, и две истории придётся сводить вручную (команда reset).

Попробуйте сами

История учебной таблицы ферментов из четырёх коммитов. В коммите 3 агент «привёл единицы»: пересчитал температуры в кельвины, а подпись столбца оставил «°C». В коммите 4 добавил новый фермент. Нажимайте на коммиты, чтобы увидеть снимок, затем исправьте ошибку одним из двух способов.

Данные условные. Проверка — как в уроке 19: значения в разумных пределах и контрольный вопрос «сколько ферментов с оптимумом не ниже 60 °C» (по источникам — 3).

А если агент сделал за сессию двадцать коммитов и что-то сломалось? Не читайте все подряд. Попросите агента найти первый плохой коммит делением пополам: он проверяет середину истории контрольным вопросом и отбрасывает половину — двадцать коммитов сужаются до одного за пять проверок5.

Граница отката

Git возвращает файлы: тексты, таблицы CSV, описания таблиц. Строки, которые испорчены в живой базе Supabase (урок 26), откат файлов не вернёт. Для данных нужны резервные копии — урок 27.

Если ключ всё-таки попал в коммит

Удалить файл следующим коммитом мало: ключ остался в истории, и любой, у кого есть копия, его найдёт6. Ключ надо сменить в сервисе, старый — отозвать.

Биотехнология

Инструкция для сборщика лежит в репозитории. После правки «бери и стабильность тоже» в ручной выборке нашлось 3 ошибки из 30 вместо нуля. История показывает, какие именно строки инструкции изменились, и правку отменяют одним коммитом, сохранив всё остальное.

Свои проекты

Сайт фундации публикуется прямо из репозитория на GitHub (как — урок 28). Агент обновил польскую версию и задел русскую. Отмена одного коммита — и через минуту сайт прежний. Ветка «новый-дизайн» живёт неделями, не трогая работающий сайт.

Сноски
  1. Git написал Линус Торвальдс в 2005 году для разработки ядра Linux. Сейчас это основной инструмент истории версий в мире программ.
  2. «Связать» — значит получить ещё один ключ доступа (урок 7). Вы один раз входите в GitHub в окне браузера, и компьютер получает ключ. Хранит его не папка проекта, а системное хранилище паролей: «Связка ключей» на Mac, «Диспетчер учётных данных» в Windows. Git сам берёт ключ оттуда при каждой отправке; в файлах проекта и в окне агента его нет. Честная оговорка: команда «покажи этот ключ» в системе существует — ещё одна причина, по которой незнакомые команды агента идут со спросом (урок 14). О ключах — урок 27. Документация GitHub: «Кэширование учётных данных GitHub в Git» (инструкция, рус., 5 мин), проверено 11.11.2026.
  3. Семь коротких правил хорошей подписи — от длины первой строки до «объясняйте что и почему, а не как» — в классической статье Криса Бимса. Хватит одного прочтения, чтобы проверять подписи агента. Chris Beams: How to Write a Git Commit Message (статья, англ., 15 мин).
  4. Как это выглядит на практике: исследователи разобрали 567 запросов на слияние, которые подготовил Claude Code в 157 открытых проектах. 84 % в итоге приняли, но почти половину люди перед слиянием дорабатывали — чаще всего исправления ошибок и документацию. Ветка плюс проверка человеком — не формальность. On the Use of Agentic Coding: An Empirical Study of Pull Requests on GitHub (статья, англ., 2025, аннотация — 3 мин).
  5. По-английски это git bisect. Двадцать коммитов → 10 → 5 → 3 → 2 → 1: пять проверок, потому что 2⁵ = 32 ≥ 20. Глава книги Pro Git на русском показывает, как это выглядит в командах; читать по желанию — команды набирает агент. Pro Git: «Обнаружение ошибок с помощью Git» (книга, рус., 10 мин).

Коммиты, сделанные вместе с Claude Code, содержали ключи примерно вдвое чаще среднего (3,2 % против 1,5 %); авторы подчёркивают, что отправлял их всё равно человек. Почти две трети ключей, утёкших ещё в 2022 году, в 2026-м всё ещё действовали. GitHub по умолчанию не даёт отправить в открытый репозиторий ключи известных ему форматов (актуально на ноябрь 2026), но это страховка: ключ необычного вида он пропустит. Частые вопросы
Я в ветке и агент в чистовике правили один CSV в разных строках. Это конфликт?Обычно нет: правки в разных местах файла Git сводит сам. Конфликт — когда задеты одна и та же или соседние строки. После любого слияния прогоните контрольные вопросы.
Кто видит закрытый репозиторий?Вы и приглашённые. Технически доступ есть и у самой компании GitHub — как у любого провайдера (урок 7). Неопубликованные черновые данные класть можно; ключи и личные данные людей — нет.
Можно ли отменить отмену?Да. Отмена — обычный коммит; его отменяют так же, и изменение возвращается.
Полгода ничего не отправляю. Копия цела?Да. Срока хранения у репозиториев на GitHub нет (актуально на ноябрь 2026).

Главное
  • Коммит — снимок проекта с подписью «что и зачем»; к любому снимку можно вернуться.
  • Рискованное делают в ветке; в чистовик сливает человек. Копия на GitHub обновляется, только когда её отправили.
  • Безопасный откат — новый коммит, отменяющий одно изменение; перемотка выбрасывает и хорошее.
  • В истории — тексты и таблицы CSV; ключи, статьи и личные данные — нет. Утёкший ключ меняют.

Сквозной проект · шаг 25

Время: ≈ 30 минут. Возьмите папку проекта под историю. Заведите бесплатный аккаунт на github.com. Поручите агенту:

  • создать репозиторий в папке pet-enzymes/;
  • файл .gitignore: .env, articles/, временные файлы;
  • первый коммит «ТЗ, журнал и принятые данные»;
  • закрытый репозиторий на GitHub и первая отправка.

Связать компьютер с GitHub агент поможет один раз: откроется окно браузера, вы войдёте сами. Папку для страницы поиска пока не создавайте — она появится в уроке 28 отдельным репозиторием.

Проверьте сами на GitHub: файла .env и папки articles/ там нет, таблицы data/ есть. Запись в journal.md, тип «сделано»: адрес репозитория и подпись первого коммита. Дальше — в конце каждой сессии: «закоммить и отправь».
