Supabase: база вместо таблицы

Чем база данных отличается от электронной таблицы, какой путь проходит запрос со страницы до базы и почему каждый видит только то, что ему разрешено.

Когда таблица перестаёт справляться

После модуля 5 у вас таблица на сотни строк измерений. С ней начинаются знакомые беды. «LCC-ICCG» в одной строке и «LCC ICCG» в другой — для таблицы это два разных фермента. Ссылка на одну и ту же статью вписана сорок раз, и в трёх местах с опечаткой. Двое правят файл одновременно, и чьи-то правки пропадают.

База данных хранит те же строки, но вместе с правилами, которые она сама и соблюдает. Температура — только число. Единица — обязательна. Измерение нельзя записать за несуществующий фермент. Таблица такие ошибки принимает молча, база отказывается.

Supabase — облачный сервис, внутри которого работает база PostgreSQL1. Вокруг неё Supabase добавляет вход для пользователей, хранилище файлов и готовый способ обращаться к базе со страницы сайта.

Две оговорки

Бесплатный проект засыпает, если неделю к нему никто не обращался: данные целы, но сайт перестаёт получать ответы, пока проект не разбудят в панели. И автоматических резервных копий на бесплатном тарифе нет — о копиях в уроке 22.

Таблицы и связи

В уроке 13 вы разложили данные на три таблицы: ферменты, источники, измерения. Теперь видно, зачем.

Образ

Библиотечный каталог. В карточке книги не переписывают биографию автора — там стоит номер его карточки. Исправили год рождения автора в одном месте — исправилось для всех его книг.

Так и здесь. У каждого фермента есть номер — ключ, по которому его находят без путаницы в написании. Строка измерения хранит не название, а этот номер. Такая ссылка на строку другой таблицы называется связью. Переименовали фермент один раз — все его 30 измерений «переехали» вместе с ним. Попробовали записать измерение за номер, которого нет, — база ответит ошибкой.

Запрос: вопрос на языке базы

К базе обращаются запросом на языке SQL. Он читается почти как английская фраза. Например, «покажи ферменты и значения, где параметр — оптимум температуры и значение не меньше 60, по убыванию»:

select enzyme, value, source from measurements where param = 't_opt' and value >= 60 order by value desc;

Писать такое самим не нужно: запрос пишет агент, а вы проверяете ответ на контрольных вопросах с известным результатом (урок 14). Полезно уметь прочитать запрос в общих чертах: из какой таблицы, с каким условием, что отбрасывается.

Попробуйте сами

Учебная мини-база: 7 ферментов, 12 измерений оптимума температуры, 10 источников. Выберите вопрос — увидите запрос и ответ базы.

Данные условные: названия ферментов настоящие, значения близки к опубликованным по порядку величин, источники S1–S10 вымышлены.

Много людей сразу и вход

Файл таблицы правит тот, кто сохранил последним. База принимает изменения построчно и следит, чтобы две правки одной строки не смешались. Связанные изменения она проводит целиком или не проводит вовсе: либо записаны и фермент, и все его измерения, либо ничего.

Чтобы база знала, кто пришёл, нужен вход. В этом курсе он через Google: вы нажимаете «Войти», Google подтверждает адрес почты, и Supabase выдаёт странице пропуск — подписанную запись «это такой-то». Дальше каждый запрос со страницы идёт с этим пропуском.

Правила доступа по строкам

Главное отличие от таблицы — шаг 5 на схеме. Правило доступа по строкам (по-английски Row Level Security, RLS) — условие, которое база проверяет на каждой строке при каждом запросе. Строки, не прошедшие условие, для запроса просто не существуют.

Живой пример — этот курс. Прогресс хранится в двух таблицах Supabase3:

  • ai_progress — пройден ли урок и результат теста. Записать или изменить строку можно только свою. Читать могут все взрослые члены семьи — для страницы прогресса.
  • ai_notes — ваши записи к заданиям. Писать — только свои, читать — только автор.

Защищает не страница, а правило в базе.

Ключ, с которым страница обращается к базе, открыт: его видит любой посетитель. Даже если кто-то напишет свою страницу с этим ключом, база не отдаст ему чужие записи — правило проверяется внутри неё. Почему открытый ключ — не секрет, а другой ключ — секрет, разберём в уроке 22.

Частая ошибка

Таблица без включённого RLS в Supabase доступна всякому, у кого есть открытый ключ. Документация Supabase требует включать правила на каждой таблице. Принимая работу агента, спросите: «на каких таблицах включён RLS и какие правила на каждой — словами?»

Биотехнология

Правило «температура от −20 до 150, единица обязательна» ловит строку «65 F» или «338» без единицы в момент записи, а не через месяц на графике. Правило «статус „подтверждено“ ставит только критик» отделяет непроверенное от проверенного прямо в базе.

Свои проекты

Расследование о фундациях: таблицы «фундации», «люди», «участие в советах». Вопрос «кто сидит в советах двух фундаций сразу» — один запрос. В таблице — ручная сверка сотен строк. А черновые заметки журналиста видит только он сам.

Задание на 10 минут

Зарегистрируйтесь на supabase.com (можно через GitHub или Google) и создайте бесплатный учебный проект. В разделе Table Editor создайте таблицу enzymes с полями «название» (текст) и «температурный оптимум» (число) и внесите три строки.

Затем попробуйте вписать в числовое поле слово «горячо» и сохранить. Запишите, что произошло, и найдите в панели, включены ли для таблицы правила RLS.

Сквозной проект · шаг 20

Перенесите данные из таблицы модуля 5 в Supabase. Поручите агенту: создать таблицы по ТЗ из урока 13, включить RLS на каждой, загрузить строки. Затем сверьте: число строк до и после, три случайные строки по исходнику, ответы базы на пять контрольных вопросов из урока 14. Запишите расхождения.
