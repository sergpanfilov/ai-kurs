После урока вы сможете описать любого агента четырьмя полями — роль, инструменты, память, права — и заранее сказать, что он сделает, чего не сможет и где может навредить.

Одна модель — разные агенты

В этом модуле у вас появятся сборщик, который вытаскивает цифры из статей, и критик, который их проверяет. Модель внутри у них одна. Чем же они отличаются?

Если у вас запасной путь: обычный Claude с доступом к папке

Задания модуля получатся и там (урок 14). Субагенты и правила прав — нет: читайте о них как о том, что будет в Claude Code.

Сначала два слова. Сеанс Claude Code, с которым вы разговариваете, — главный агент. Часть работы он может поручить субагенту — помощнику со своей инструкцией и своим окном (подробно — урок 23).

Разгадка. Сборщик и критик — одна и та же модель в разных «должностях». Различает их не ум, а описание1.

Образ

Новый лаборант. Ему дают должностную инструкцию, допуск к определённым приборам, лабораторный журнал и правило: что можно делать самому, а что — только с разрешения заведующего. Без этих четырёх вещей даже хороший специалист в чужой лаборатории бесполезен или опасен.

У агента те же четыре поля — карточка агента.

Роль и инструменты

Роль задаётся инструкцией — текстом, который ложится в окно агента первым (урок 5). «Помоги с ферментами» — не роль. «Из статьи извлеки измерения по формату из ТЗ; к каждой цифре приложи дословную цитату; цифр нет — напиши „нет данных“» — роль2. В ней одна задача, точный вид результата, признак готовности и что делать при сомнении.

Инструменты — список действий агента: прочитать файл, найти фразу, создать файл, запустить команду (урок 14). Чего нет в списке, того агент сделать не может.

В Claude Code субагент — обычный текстовый файл. Вот сборщик целиком:

Файл субагента 
---
name: collector
description: измерения из одной статьи
tools: Read, Grep, Write
model: sonnet
---
Прочитай одну статью, которую назовёт главный агент.
Формат строки — в TZ.md.
К каждой цифре — дословная цитата и страница.
Цифр нет — одна строка «нет данных».
Результат запиши в data/draft/<имя статьи>.csv.
Другие файлы не меняй.

Между чёрточками — шапка: имя, описание (по нему главный агент решает, когда звать помощника), инструменты, модель. Ниже — роль. Актуально на ноябрь 20263.

В строке model — одно из слов sonnet, opus, haiku: субагенту можно дать модель подешевле, чем у главного. Сколько это экономит, посчитаете в уроке 23.

Точка в начале имени папки .claude значит «служебная»: в окне папок такие по умолчанию скрыты. Чтобы увидеть файл, попросите агента его показать.

Осторожно

Без инструмента, чтобы открыть источник, агент обычно не говорит «не могу», а отвечает по памяти модели — с ошибками из урока 6. Поэтому статьи кладут в папку articles/.

Память — это файлы

Веса модели заморожены, а окно живёт один сеанс. Всё, что должно пережить сеанс, записывается в файлы. В начале работы агент читает их — и «вспоминает». Поэтому память — это просто то, что агент знает в начале, и всё это попадает в окно.

У Claude Code два таких механизма (урок 13)4: файл правил CLAUDE.md пишете вы, автоматические заметки агент ведёт сам — их открывает команда /memory.

Что из этого получает субагент? CLAUDE.md — да. Автоматические заметки главного и историю вашего разговора — нет: он начинает с чистого окна, и это пригодится критику. Отсюда практическое правило: общее для всех агентов держите в CLAUDE.md и TZ.md, а не «в разговоре».

Не записали решение — следующий запуск о нём не узнает. Журнал journal.md — не бюрократия, а память команды агентов.

Привал. Три поля заполнены: роль — текст, инструменты — строка в файле, память — файлы. Осталось четвёртое, самое трудное: права.

Права: замок и просьба

Права отвечают на вопрос «что агент делает сам, что — после вашего „да“, а что запрещено совсем». Общую строгость задаёт режим (урок 14). Точнее работают правила прав — три списка: запретить, спросить, разрешить. Они лежат в файле .claude/settings.json проекта, там же, где запрет из урока 14. Дописывает их агент по вашей просьбе (в терминале есть и команда /permissions). В примере — два списка из трёх:

"deny": ["Read(./.env)"],
"ask":  ["Edit(./data/measurements.csv)", "Bash(rm *)"]
  • deny — запретить. Read(./.env) — чтение файла с секретами.
  • ask — спросить. Edit(./data/measurements.csv) — любая правка или перезапись принятой таблицы: только после вашего «да».
  • Bash(rm *) — команда, которая начинается с rm (remove, «удалить»); звёздочка — «что угодно дальше».

Порядок проверки — на схеме урока 14: запрет первым, «спросить» срабатывает в любом режиме.

Теперь осторожно со словом «правила»: в проекте есть два разных файла, и работают они по-разному.

Что этоГде лежитЗамок или просьба

Главное ограничение правил прав: их нельзя написать «только для сборщика». Они действуют на всех агентов проекта — и на главного, и на субагентов5.

Различают агентов две вещи. Замок — список инструментов в карточке: у критика нет инструмента правки, и никакая инструкция его не добавит. Просьба — текст инструкции: «пиши только в свой файл». Документация Claude Code прямо называет такой текст контекстом, а не принудительной настройкой.

«Сборщик пишет только в свой файл». Это замок или просьба? И чем её подстраховать?

Просьба: правилом прав запереть на один файл можно только всех агентов сразу. Подстраховка — порядок работы: ошибка сборщика останется в черновике, а дальше её ждут критик и ваша выборка.

Правила прав — надёжный замок для обычных действий. Обойти их может программа, которую агент напишет и запустит сам. Поэтому у субагентов проекта в списке нет Bash, а запуск программы главным агентом в режиме Accept edits требует вашего «да»6.

Когда правила прав записаны, правило «только Manual» из урока 14 заканчивается: переходите в Accept edits. Выигрыш — не жать «да» на каждой записи черновика. Плата — правку вы увидите уже сделанной.

Права выдают под задачу, а не из доверия.

Критику не нужно право исправлять таблицу: его дело — вердикт, одно из трёх слов. В черновик вердикты вписывает главный агент (как именно — урок 22). Чем уже права, тем меньше вреда от любой ошибки — своей или навязанной чужим текстом.

Соберите две карточки

Критику удобно дать инструмент правки: сам впишет вердикт в таблицу. Чем, по-вашему, заплатят за это удобство?

Критик читает чужие статьи. Если в статье окажется строка-приказ, агент с правом правки изменит черновик напрямую. Без инструмента правки он может только вернуть одно из трёх слов. Проверьте себя в карточке критика, поле 2.

Попробуйте сами

Заполните карточки сборщика и критика для проекта ферментов. Неверные варианты здесь не глупые: у каждого есть своё удобство. Выберите вариант — разбор под ним назовёт цену этого удобства. Ответ можно поменять.

Варианты условные. Разбор — мнение автора курса: где годятся два варианта, приняты оба. «Сначала» очищает открытую карточку.

Что вы увидели. У каждого лишнего права или лишнего знания есть удобство — и цена. Карточку заполняют от задачи: что агенту нужно, чтобы её сделать, и ничего сверх.

Биотехнология

Сборщик читает статью и пишет свой файл черновика. Принятую таблицу он без вашего «да» не изменит — это замок: правило «спросить». А «не трогай чужие файлы черновика» — просьба. Нарушит её — ошибка останется в черновике, а основная таблица цела.

Свои проекты

В файле правил этого курса записано: «ничего не удалять без подтверждения», «публиковать только с согласия Сергея». Это память — и просьба. Чтобы публикация физически не прошла без «да», команду отправки на сайт ставят в список «спросить».

Сноски
  1. Та же мысль в привычной для статей схеме «агент = модель + планирование + память + инструменты», с разбором видов памяти: Selectel: «Как устроены LLM-агенты: архитектура, планирование и инструменты» (статья, рус., 2025, 14 мин). Код в середине можно пропустить.
  2. Как писать инструкции «на правильной высоте» — не жёсткий список «если — то» и не расплывчатое «помоги» — и почему начинать стоит с короткой, дописывая её по замеченным ошибкам: Anthropic: Effective context engineering for AI agents (статья, англ., сентябрь 2025, 25 мин). Там же — инструменты, заметки и субагенты: по сути, все четыре поля карточки.
  3. Файл можно положить и в ~/.claude/agents/ — тогда помощник доступен во всех проектах. Кроме полей из примера, в шапке бывают список запрещённых инструментов, свой режим разрешений и своя память субагента. Там же сказано, что субагент получает CLAUDE.md, но не историю разговора и не автоматические заметки. Документация: Create custom subagents (англ., 20 мин; хватит разделов о шапке файла и о том, что субагент видит в начале), проверено 11.11.2026.
  4. В начале сеанса из автоматических заметок загружаются первые 200 строк (до 25 КБ), остальное агент дочитывает по необходимости. Как посмотреть и поправить, что агент записал о проекте: How Claude remembers your project (документация, англ., 15 мин). Полезно открыть рядом со своей папкой.
  5. Можно ли запереть субагента на один файл? Строкой в шапке или правилом — нет. Для этого есть «хуки»: маленькие программы, которые проверяют каждое действие агента перед выполнением. Это уже программирование, в курсе они не нужны. Правила по путям ловят встроенные инструменты чтения и правки и распознанные команды, но не программу, которая открывает файлы сама. Документация Claude Code: Configure permissions, проверено 11.11.2026.
  6. Ещё на шаг надёжнее — ограничение на уровне операционной системы: агент физически видит только свою папку и ходит только на разрешённые адреса. Как это сделано в Claude Code и почему вопросов стало на 84 % меньше: Anthropic: Making Claude Code safer with sandboxing (статья, англ., октябрь 2025, 10 мин).

Главное
  • Агента описывают четыре поля: роль, инструменты, память, права.
  • Субагент в Claude Code — файл в .claude/agents/: шапка с именем, инструментами и моделью, ниже роль.
  • Память агента — файлы: что не записано, следующий запуск не узнает.

Задание на 10 минут

Что получится: карточка вашего агента из четырёх полей — и одно место, где агент ошибся о самом себе.

  1. Откройте Claude Code в папке проекта (или запасной путь).
  2. Спросите агента:
    Какие у тебя сейчас инструменты? Что ты можешь сделать без моего подтверждения? Какие файлы ты читаешь в начале работы?
  3. Сверьте ответ с тем, что записано на деле: правила прав — в файле .claude/settings.json, подключённые сервисы — в списке коннекторов (в терминале — /mcp), заметки — по команде /memory. О себе модель тоже может ошибиться (урок 6).
  4. Запишите карточку, одно расхождение между ответом агента и экраном и одно право, которое для вашей задачи лишнее.
Сквозной проект · шаг 20

Что получится: два файла субагентов — сборщик и критик — и три правила прав в настройках проекта.

Сегодня — две карточки и правила

  • Сборщик — читает одну статью и пишет свой файл data/draft/<имя статьи>.csv (урок 21). Инструменты: Read, Grep, Write.
  • Критик — сверяет строки с источником; записи у него нет, вердикты он возвращает главному (урок 22). Инструменты: Read, Grep.
  1. Напишите для каждого карточку: 2–3 предложения роли, список инструментов, файлы памяти и права в три строки — «сам», «со спросом», «запрещено», с пометкой «замок» или «просьба» у каждой.
  2. Попросите Claude Code записать карточки — сначала сборщика, потом так же критика (critic):
    Создай субагента collector в папке .claude/agents/ по этой карточке: (вставьте карточку)
  3. Попросите дописать три правила из примера урока:
    Допиши в .claude/settings.json три правила: запретить Read(./.env); спрашивать Edit(./data/measurements.csv) и Bash(rm *). Потом покажи мне файл целиком.
  4. Проверьте по показанному файлу, что все три правила на месте.
  5. Перейдите в режим Accept edits.
  6. Запишите в journal.md «решение»: какие агенты, что заперто замком, что держится на просьбе.

Можно позже — ещё две карточки
